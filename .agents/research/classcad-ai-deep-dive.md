# classcad-ai deep dive: what LAZERS should take

Scope: every new idea in `awv-informatik/classcad-ai` (HEAD `586914e`), ranked by how much it would help LAZERS. Context size is one axis among several. The clone was only read; nothing was run.

Path prefixes:

- **cc:** `classcad-ai/repo/packages/`
- **pine:** `pine/repo/`
- **lz:** `/Users/tjw/Documents/ChatGPT/opencode-lazers/`
- **oc:** `lz:node_modules/@opencode/`

Every line number below was checked against the source. Where the Haiku index was wrong or incomplete, the correction is noted.

Licence: MIT, `Copyright (c) 2026 AWV Informatik AG` (cc:buerli-ai/LICENSE:1-3; the other packages ship the same LICENSE file). The repo root has no LICENSE. Reimplementing an idea needs no notice. Copying code does (for example `checkWireInvariants` from cc:buerli-ai/src/context/render.ts:67-85, or `thresholds` from cc:buerli-ai/src/context/policy.ts:260-263): the copyright and permission notice must then ship with LAZERS. Recommendation: reimplement from scratch and credit the source in a design note.

Evidence caveat: the repo contains no eval data. Its "measured" claims, such as "1 question → 6/6 correct" (cc:buerli-ai/src/agentLoop.ts:438-439) and "maxLevel 31 silent failures" (cc:skill/recipes/verification.md:3-6), are unverifiable. Two findings:

- **The waste is count, not size.** `outcomeText` already reduces evidence to IDs (`lz:src/runner/outcome.ts:96-101`). The raw accepted payload maximum is 126 KB; rendered, the maximum is 4 KB.
- **Supersession stops at delivery.** It works only while a notice is still pending (`lz:src/runner/outcome-delivery.ts:29-38`). After that, each notice stays in the Architect transcript until OpenCode compacts it (an LLM summary) or LAZERS renews the session.

On the 551-notices session: ≥476 rows (86%) have a newer notice for the same plan. Some rows were merged into one message, so the message count is lower; the volume of text is not.

The OpenCode hooks that make classcad's approach possible (oc:plugin/dist/effect/session.d.ts):

- `session.hook("context")` gets mutable `system`, `messages` and `tools` for each request (`:26-43`). It also exposes each stored message's `metadata` read-only (`:22-25`).
- `session.hook("compaction")` can set `result` and **skip the model request** (`:44-53`).
- `experimental.idle` can admit input before the session goes idle (`:155-169`).

LAZERS uses the context hook today only to strip delegation tools from workers (`lz:src/runner/roles.ts:101-107`). Notices are `session.synthetic` messages that carry `lazersOutboxID` / plan metadata (`lz:src/runner/native.ts:1195-1203`, `lz:src/runner/outcome-delivery.ts:57,73`). The context hook can therefore identify each notice and which plan it covers without guessing.

## 2. How classcad's compaction works

| Question           | Answer                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Classification** | `kindOf` sorts each result into one of four kinds (cc:buerli-ai/src/context/annotate.ts:81-103):<br>- **reference**: docs, list_methods, text from fetch_url<br>- **state-read**: tree, find, inspect, get_selection, snapshot, and scripts proven read-only<br>- **record**: delegate, ask_user, notes, fetched images<br>- **build**: everything else<br>A script counts as read-only only if every engine op matches `^(get\|calculate\|is[A-Z]\|evaluate\|export\|save\|requestVisualisation)` and it touches no non-core namespace. In doubt, it counts as mutating (`:50-64`).                        |
| **Dead**           | `restore` / `load_file` mark the state-reads and builds after the checkpoint step. Docs, records and checkpoints are exempt. The marking happens immediately, but stubs are applied only at the next compaction, "because the failed attempt is what the model needs next" (`:250-272`).                                                                                                                                                                                                                                                                                                                    |
| **Superseded**     | A newer live result has the same signature (`tree`, `find:[type,name]`, `inspect:id`, `selection`, `notes`; `:105-121`). For docs, every served key appears in a later docs result (cc:buerli-ai/src/context/policy.ts:148-160).                                                                                                                                                                                                                                                                                                                                                                            |
| **Stale**          | A state-read whose epoch is below the current one (`policy.ts:165`). The epoch advances once per batch that mutated anything, so a read in the same batch as a mutation is stale immediately (annotate.ts:216-248). A new user turn starts a new epoch, because the user may have edited the model (`:31-48`).                                                                                                                                                                                                                                                                                              |
| **Replacement**    | `{"condensed": "<reason>. (<tool>: <digest>)"}`. The digest is one line per tool, with failures first (annotate.ts:167-214). A docs stub names the keys and says "REFETCH … do NOT reconstruct from memory" (policy.ts:103-108).                                                                                                                                                                                                                                                                                                                                                                            |
| **When**           | Before each round, if the estimate exceeds the trigger (cc:buerli-ai/src/agentLoop.ts:194-206):<br>- trigger = max(2000, min(0.85·limit, limit − maxTokens))<br>- the lower trigger (0.75×) applies at safe points: the first iteration, or after a read-only batch<br>- target = 0.5·limit (policy.ts:260-263)<br>Retries stop once an attempt reclaims nothing (`exhaustedAt`, agentLoop.ts:198-202). On a provider overflow error: one hard pass to 0.4·limit with `keepGroups: 2`, then one retry (`:241-253`).                                                                                         |
| **Tier order**     | Within one call: A (dead, superseded, stale, largest first) → B (bulk stubs on build/record/run_script, input elision over 400 chars, then lookups, then docs oldest first) → C (collapse groups oldest first, then regenerate one journal plus a state block). Each tier stops at the target (policy.ts:147-238). Protected: the last 4 groups, reference-image groups, ask_user groups, closing answers, and the last 2 delegate reports (`:73-89`).                                                                                                                                                      |
| **Cache**          | Stored history is never rewritten; flags are set only at events (render.ts:1-9). The state block is pushed once at a collapse and replaced at the next (policy.ts:229-237), so it can go **stale** between compactions. The index's "could not determine" item 1 still stands: no `cache_control` code was found, so the "keeps caching working" claim (render.ts:8-9) is unproven.                                                                                                                                                                                                                         |
| **Tests**          | Pure-function tests against `dist` (cc:buerli-ai/test/context.test.mjs:1-41 harness through the real annotate/advance), 13 of them: read-only detection `:43`, epochs `:54`, turn boundary `:71`, restore and load_file `:81,99`, served doc keys `:106`, image estimate `:111`, tier A only `:144`, full run with wire invariants and the stored copy untouched `:158`, stability and idempotence `:195`, single ledger `:205`, elision marker `:219`, journal priority `:230`.<br>Loop tests: compaction at threshold, single overflow retry, history preserved (cc:buerli-ai/test/loop.test.mjs:44-138). |

const lastNotice = new Map<planID, msgIndex>()
const lastRead = new Map<sig, msgIndex>()
messages.forEach((m, i) => {
  for (p of planIDs(m.metadata)) lastNotice.set(p, i)
  if (sig(m)) lastRead.set(sig(m), i)

  if (isSubmit(m) && facts.accepted(ref(m)))

## 4. Not worth it

- **Hard `capJson` caps** (#7). They refuse data, and LAZERS has no script that could re-query a slice. Keep only the explicit-marker part.
- **classcad's token estimator and overflow-error parsing** (#16). OpenCode reports real context tokens.
- **Loop-level retries, nudges and closing unanswered tool calls** (#18). OpenCode owns the loop.
- **Sub-agent fresh history and no re-delegation** (#12). Done (lz:src/runner/roles.ts:101-120).
- **Per-call drawing IDs, the daemon and the serialized queue** (#13). The plugin runs in-process with SQLite fences.
- **Doc aliases and synonym BM25** (cc:skill/discovery.js:701-707,15-40). LAZERS would have a handful of docs; a key index is enough.
- **Image/byte withholding** (cc:buerli-ai/src/agentLoop.ts:701-735). Already done in spirit: evidence is reduced to IDs (lz:src/runner/outcome.ts:96-101).
- **The renderer, share hub, relay and checkpoint store.** CAD-specific.
