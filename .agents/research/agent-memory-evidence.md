# Do agent memory systems help LLM agents? Evidence review

Scope: published evidence as of 2026-11-20. Every claim cites a source that was fetched in this session unless marked **[search-only]** (seen in a search snippet, not opened) or **[not reached]**. Vendor-authored work is labelled.

## 1. What "agent memory" means in practice

| Class                                                      | Examples                                                       | What it is                                                              | Evidence bearing on it                                                                                  |
| ---------------------------------------------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| (a) Long-term conversational/user memory stores            | MemGPT/Letta, Mem0, Zep                                        | Extract facts from past chats into a store; retrieve at answer time     | Benchmarked on QA about past chats (LoCoMo, LongMemEval, DMR). Not benchmarked on coding task success.  |
| (b) Retrieval over vector/graph store of past interactions | Mem0 graph, Zep temporal KG, LangMem, Supermemory, OpenViking  | Same as (a) with explicit retrieval layer                               | Same as (a); coding evidence in section 3                                                               |
| (c) Plain files the agent reads/writes                     | CLAUDE.md, AGENTS.md, memory dirs                              | Human- or agent-written markdown in repo or home dir                    | Studied as instruction files (section 4); a filesystem agent beat Mem0 on LoCoMo (section 2)            |
| (d) Reflection / experience memory for task agents         | Reflexion, ExpeL, AWM, MemGovern, SWE-ContextBench "summaries" | Store lessons or trajectories from past tasks; inject into future tasks | Only class with task-success numbers, mostly on non-coding benchmarks or proposer-run coding benchmarks |
| (e) In-session context management                          | Compaction, summarisation                                      | Shrinks the live context window                                         | Not studied as "memory" here beyond context-rot evidence (section 3)                                    |
| (f) Codebase knowledge                                     | Repo maps, indexes, code search                                | Derived index of the repo                                               | Usually mislabelled as memory; no evidence reviewed separately                                          |

Class (c) and (f) are the ones most coding-agent users actually run. Classes (a) and (b) are the ones with vendor benchmarks.

## 2. Benchmarks

### 2.1 Conversational QA benchmarks

**LoCoMo** — Maharana et al., arXiv:2402.17753, submitted 2024-02-27. About 300 turns and 9K tokens per conversation, up to 35 sessions. Tasks: QA, event summarisation, multimodal dialogue. Measures question answering over past chats. Judge-based scoring (J).

- Known problems, from the **vendors and their critics** (no neutral arbiter found):
  - Zep's critique of Mem0 (blog, dated 2025-05 by page metadata): alleges Mem0 misconfigured Zep (user roles, timestamps in text not `created_at`, sequential search). Corrected Zep score 75.14% ± 0.17 (author's own rerun). Also argues Category 5 lacks ground truth. Blog is self-serving: Zep sells a memory product. Its own date metadata and body disagree on the margin (24% vs 10%). Source: https://www.getzep.com/blog/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory/ (fetched via redirect from blog.getzep.com).
  - Mem0 reports Zep 65.99%, Mem0 Graph 68.44%, Mem0 Base 66.88%, and GPT-4o-mini full-context 72.90% (per the Zep blog's reproduction of Mem0's chart). Source: same as above.
  - Letta (2025-08-12): filesystem agent reached 74.0% on LoCoMo with GPT-4o mini, above Mem0's reported 68.5%. Letta calls the cross-system comparison "apples to oranges," and says Mem0 did not answer requests for clarification. Letta sells a memory product. Source: https://www.letta.com/blog/benchmarking-ai-agent-memory
  - Penfield Labs audit (DEV post, April; year not shown, likely 2026): claims 99 of 1,540 LoCoMo answers (6.4%) are wrong; judge accepts 62.81% of intentionally wrong but topically adjacent answers. Repo `dial481/locomo-audit` cited but not inspected. **Penfield describes itself as a memory vendor and does not disclose this in the post.** Source: https://dev.to/penfieldlabs/we-audited-locomo-64-of-the-answer-key-is-wrong-and-the-judge-accepts-up-to-63-of-intentionally-33lg
  - Mem0's own 2025 paper (arXiv:2504.19413, 2025-04-28): reports ~26% relative J gain over OpenAI memory, ~91% lower p95 latency and >90% lower tokens vs full-context. Self-reported; no independent replication in the abstract. Source: https://arxiv.org/abs/2504.19413
  - **[search-only]** Mem0 has reportedly published 91.6–92.5% LoCoMo in 2026 after a pipeline rewrite; not verified against Mem0's materials, and not rerun by Letta.

**LongMemEval** — Wu et al., arXiv:2410.10813, submitted 2024-10-14, ICLR 2025. 500 questions over five abilities (extraction, multi-session reasoning, temporal reasoning, knowledge updates, abstention). Headline: commercial assistants and long-context LLMs show a ~30% accuracy drop on sustained interaction. Source: https://arxiv.org/abs/2410.10813

- Critique: Penfield audit argues LongMemEval-S mainly measures context-window capacity, citing a Mastra post (full-context 60.20% vs observational memory 84.23%, gpt-4o). Vendor-sourced. Same audit link as above.

**DMR (Deep Memory Retrieval)** — introduced in the MemGPT paper, arXiv:2310.08560 (2023-10-12). The abstract fetched does not report DMR numbers. Zep reports DMR 94.8% vs MemGPT 93.4% (arXiv:2501.13956, 2025-01-20). The margin is 1.4 pp, and all numbers are self-reported by Zep. Sources: https://arxiv.org/abs/2310.08560 ; https://arxiv.org/abs/2501.13956

**MemoryAgentBench** — Hu & Wang, McAuley, arXiv:2507.05257 (2025-07-07, revised to v4 2026-06-28). Four competencies: accurate retrieval, test-time learning, long-range understanding, selective forgetting. Conclusion from abstract: "current methods fall short of mastering all four competencies." Numbers were not in the abstract; the full paper would be needed for the memory-agent vs long-context comparison. Source: https://arxiv.org/abs/2507.05257

### 2.3 Where the benchmarks disagree

- A filesystem agent with grep and no memory store (Letta, 74.0%) beat the best Mem0 number on LoCoMo (68.5%). A plain full-context baseline (72.9%) also beat Mem0's best number, per the Zep reproduction. The gap is largely about evaluation setup, not architecture: Letta and Zep both allege misconfiguration of the competitor.
- LoCoMo conversations (~9K tokens; ~16–26K in some counts) fit in a modern context window, so the benchmark does not test memory pressure. Penfield and Zep both argue this. Penfield's 6.4% answer-key error rate sets a ceiling near 93.6%.
- No neutral head-to-head exists for coding agents. VibeMemBench (2026) is the first found that matches memory-off baselines across four memory systems, and it is the least favourable to memory systems.

## 3. Evidence for coding agents: does memory help?

### 3.1 Positive, with caveats

- SWE-ContextBench (2026): oracle summaries of prior tasks improve resolve rate by about 1–5 pts across five agents and cut tokens 14–29%. Realistic retrieved memory (Mem0, OpenViking, Supermemory) is mixed: −2 to +4 pts on one model. Source: https://arxiv.org/html/2602.08316
- MTL (2026): cross-domain "insight" memories +3.7% average Pass@3; self-generated memories beat cross-model memories (Table 6). Source: https://arxiv.org/html/2604.14004v1
- Gains are small (1–5 pts) relative to typical run-to-run variance on SWE-bench, and no paper reviewed reports seed variance or confidence intervals in its abstract. **Treat as unconfirmed until replicated.**

### 3.2 Negative and cautionary

- **Retrieval noise.** SWE-ContextBench: "unfiltered or incorrectly selected context provides limited or negative benefits." Free summary learning −4.04 pts and higher cost. Source: https://arxiv.org/html/2602.08316
- **Negative transfer.** MTL: low-level traces transfer poorly; benchmark-level drops up to ~−0.09 Pass@3 on some tasks. Source: https://arxiv.org/html/2604.14004v1
- **Null on memory systems.** VibeMemBench: 11/12 memory-system conditions did not exceed memory-off. Source: https://arxiv.org/abs/2609.23570
- **Context rot.** Chroma (2025-07-14, 18 LLMs): performance degrades with input length even on trivial tasks (repeated words), and semantically similar distractors reduce accuracy; four distractors compound the drop. Vendor report (Chroma sells retrieval infrastructure), but replication code is public. Source: https://www.trychroma.com/research/context-rot
- **Memory poisoning.** MINJA (arXiv:2503.03704, 2025-03-05, rev. 2026-02-12): injects malicious records through ordinary queries without write access to the memory bank. Abstract cited; the injection and attack success rates (98.2% / 76.8% are from search snippets) were **not verified** against the paper. A 2026 follow-up (arXiv:2601.05504) studies memory poisoning in EHR agents and defenses. MemoryGraft (arXiv:2512.16962) plants poisoned "successful experiences." Sources: https://arxiv.org/abs/2503.03704 ; https://arxiv.org/html/2601.05504
- **Stale memory.** No controlled paper reviewed directly measures stale-fact harm in coding agents. **Unproven.**

### 3.3 Cost

- Memory retrieval and summaries reduce tokens in SWE-ContextBench (14–29%) and Mem0 reports 90% token savings vs full-context on LoCoMo (self-reported). These are the only cost numbers found for memory systems; coding-agent cost data beyond SWE-ContextBench was not found.

## 6. Synthesis

- **Dedicated memory system (vector/graph store, Mem0/Zep-class):** Evidence supports it only for long-horizon conversational QA, and even there the leading comparison is contested. For coding agents, the strongest 2026 result (VibeMemBench) says current systems do not reliably beat no-memory. **Unproven for coding; not shown to be better than files.**
- **File-based memory (AGENTS.md, notes, memory directories):** Small benefit at best when hand-written and minimal. LLM-generated files and long files cost ~20% more and can reduce success. Use for facts the codebase cannot show: build commands, conventions, decisions. **Evidence-supported as cheap; benefit is small.**
- **Experience/reflection memory across tasks:** Shows a few points of gain in controlled coding experiments, with negative results from noisy or over-specific memories. **Shown in controlled experiments, small effect; not production-proven.**
- **Harmful or risky:** Stuffing large retrieved context (context rot), unfiltered retrieval, unvetted writable memory (poisoning). Keep retrieved context small and curated.
- **Codebase indexes (class f):** Not reviewed as memory. Treat as a separate question.

## 7. Method and limits

- Primary sources were fetched. Abstract-only fetches (for example LoCoMo, Mem0 2025, Zep 2025, Reflexion, MINJA, MemoryAgentBench) give the metric and framing but not full tables. Numbers from them are only as reliable as the abstract.
- Not reached in detail: MemoryAgentBench results table, SWE-Bench-CL results, ExpeL results, Generative Agents, Voyager, A-MEM, MemGPT DMR table, Mem0 2026 numbers, MINJA tables, Cognee/LangMem internals. Any claim that depends on these is marked above.
- Commercial conflicts: Zep, Mem0, Letta, Penfield, and Chroma all sell memory or retrieval products. Their own benchmark papers and posts are proposer-run.
- Dates: arXiv dates are submission dates of v1 unless stated. The Zep blog's date comes from page metadata and may be off.
