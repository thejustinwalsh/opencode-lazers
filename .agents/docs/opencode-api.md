# OpenCode V2 API lookup

**OpenCode 2.3.0 · checked 2026-11-18**. Single-page index of the public extension surfaces, not an implementation plan. Coverage: every server-plugin context domain and hook, Desktop window/main APIs and registries, TUI APIs and slots, RPC, client/embedded SDK, and all **170 HTTP operations in 32 resource groups**, with **501 linked schemas**.

**Authority:** API names link to source at commit `dc2ffcf` (release `v2.3.0`); documentation links explain usage. Follow the linked definition for signatures, payloads, permissions, errors, and lifecycle before implementing. **E** means explicitly experimental; unmarked entries are not a promise of long-term stability. [OpenAPI contract][protocol] · [schema definitions][schemas] · [live API browser](https://opencode.ai/v2/docs/api).

## Server plugin context

`ctx` is a restricted in-process API, **not the entire network client**. Metadata: `app.{name,version,channel}`, `location` (directory/project/workspace), `options`. Transforms edit registries synchronously; `reload()` replays them when captured inputs change. Registrations expose `dispose()`. [Lifecycle and transforms](https://opencode.ai/v2/docs/build/plugins/server/#lifecycle) · [complete context][p-plugin].

### Main process and IPC

[MainContext][g-main] adds `onCleanup`, synchronous `storage.store/remove`, `log.write`, `serverEndpoints.get`, `windows.get/list/focused/on`, `embeds.create`, `cli.{version,command,binary,development}`, and `provide(Ipc, implementation)` to shared context. Node/Electron integrations run here. IPC provides typed methods/state/events; main registration has `changed/emit/dispose`, windows use methods/state/on. [IPC contracts][g-core].

`ctx.use` returns reactive `Live<T>` pending/active/inactive states. Respect provider loss and cleanup; neither app internals nor arbitrary window hooks are public. `/gui/host`, `/gui/builtin`, `/gui/updater`, and unlisted `/gui/*` subpaths are private in [package exports][package].

## RPC and client helpers

[Rpc.define][rpc] declares `id`, `methods.{input,output,errors}`, `events.{schema}` using JSON Schema/Standard Schema; Effect definitions use the Effect API. [`ctx.rpc.register`][p-rpc] supplies handlers with `{signal,error}` and returns `events.emit/dispose`. Call through `ctx.rpc(definition)` or `client.rpc(definition)`; [typed subclients][client-rpc] expose `events.on/subscribe`. Object event payloads carry location; `rpc.*` error names are reserved. [RPC guide](https://opencode.ai/v2/docs/build/plugins/rpc/).

[Client][client] operations accept request options including cancellation/headers. Native/RPC event streams are shared, live-only, with no replay or automatic reconnect: resubscribe and resync after failure. [Service][service] offers `discover/ensure/stop/headers` (`ensure` can start a local server); [client MCP][client-mcp] `connectClientMcp` exposes caller-owned tools over WebSocket; [media helpers][media] `mediaHashFromUri/withMediaRefs` control referenced attachment retrieval. `/solid` provides reactive client data; `/effect` and `/effect/service` offer Effect equivalents.

The [event manifest][events] indexes event names and payloads, including execution/step/tool/usage, inbox/forms/permissions, registry changes, filesystem/LSP, shell/worktree/VCS, TUI, and RPC events. The [configuration schema][config-schema] is the complete lookup for agent/model/tool/permission/MCP and experimental feature settings.

Public `location.reload()` is server-wide across loaded locations, not scoped to the caller's worktree: the [pinned handler](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/server/src/handlers/location.ts) calls [`LocationServiceMap.reload`](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/core/src/location-service-map.ts#L20-L36), which invalidates all loaded refs and boots their replacements. The client signature is `location.reload(requestOptions?): Promise<void>`; there is no location input. The [local source loader](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/plugin/src/source.bun.ts) tracks the import graph and evicts its local import cache before loading. Coordinate a quiet boundary outside an in-flight tool call: pending forms/permissions are cancelled, and running sessions continue at the next step boundary. A GUI reload is separate. Verify effective behavior through the actual feature call after reload, not source inventory alone.

For a removed inactive checkout, `debug.location.list()` exposes cached locations;
`debug.location.evict({location:{directory}})` invalidates that exact location.
The [debug handler](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/server/src/handlers/debug.ts)
uses the request's location key and does not explicitly boot a replacement. Check
active session placement and the target's completed cleanup before retiring it.

`ctx.worktree.create` forwards to the in-process core service; its typed failures
are not necessarily the HTTP protocol `WorktreeError` envelope. Check the
[plugin bridge](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/core/src/plugin/host.ts#L548-L566)
and exercise actual Effect/core error shapes when preserving native failure data.

Local server-plugin module identity is not shared state: the pinned [local source loader](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/plugin/src/source.bun.ts) evicts its local import graph when preparing each location. Two loaders of the same canonical entry can retain different module-local objects. Use explicit process-shared or durable state when coordinating locations; one configured path alone does not establish sharing.

## Scheduling and LAZERS feature routing

| Feature                            | Native API to extend and boundary                                                                                                                                                                                                                                                                                       |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Architect and task contracts       | Agent config/files + `ctx.agent.transform`; schema-bound `ctx.tool.transform`/RPC; task semantics are LAZERS-owned. [Agents](https://opencode.ai/v2/docs/agents/) · [tools][p-tool].                                                                                                                                    |
| Timed/recurring execution **E**    | `client.experimental.schedule.create/list/get/pause/resume/delete`; requires session config `experimental.schedules`. `when` supports delay/absolute/interval/cron with timezone; conditional/until checks and failure policy are in [Schedule.Request][schedule-schema]. [Routes][schedule]. No `ctx.schedule` exists. |
| Dependency scheduler and workers   | `ctx.session.create/switchAgent/switchModel/prompt/wait/interrupt`, events, worktrees, storage; LAZERS owns DAG readiness, concurrency, integration, attempt accounting, recovery. Timed prompts are not a DAG scheduler.                                                                                               |
| Skill and model policy             | `skill/provider/model` transforms, prompt/context hooks, `session.instructions.entry` **E**; provider/transport hooks for cache and routing controls.                                                                                                                                                                   |
| Budgeting and verification         | Permission/tool/shell/retry hooks, `session.interrupt`, usage/step/tool events and `experimental.session.stats`; LAZERS owns acceptance, command deduplication, repository execution policy and measured usage accounting.                                                                                              |
| State, memory, SQLite              | Server `ctx.storage` exposes durable JSON keys, not raw SQL. Desktop stores are separate. A relational task DB needs an explicit SQLite integration/location contract; do not assume access to the host's private database.                                                                                             |
| Editing, LSP, filesystem, research | Tool transforms replace/wrap tool implementations (including an editing experiment); client file/reference/search APIs and config support surrounding capabilities. No dedicated public LSP or hashline domain is declared.                                                                                             |
| Desktop dashboard and approvals    | `Panel/SettingsPage/Command/Slot`, dialogs, typed server RPC, live events, main IPC/native integrations; LAZERS supplies task graph, evidence, and approval UI.                                                                                                                                                         |
| Telemetry and recovery             | Event subscriptions, session logs/stats/context/inbox, storage, debug and service lifecycle; persist checkpoints and reconcile live state because subscriptions do not replay.                                                                                                                                          |

**Maintenance:** when OpenCode changes, diff [package exports][package], [server context][p-plugin], [hook types][p-session], [GUI registries/context][g-context], [TUI context][t-context], and [OpenAPI][protocol]. Update counts and source revision together; retain one row for every resource and extension domain.
