# Native worker liveness evidence — 2026-11-02

## Behavior

- The runner uses the authenticated, cached native V2 transport and reads the
  responding process identity once at connection. A failed native request
  invalidates that client so a later operation can rediscover; heartbeats do not
  repeatedly probe service discovery.
- Worker observations combine native foreground execution, inbox/input state,
  worker-location-scoped permission/form requests, persisted timestamps and
  stable message-detail reads. An absent handle with in-flight timestamps is
  interrupted/reconcilable; stale success, an unfinished latest assistant,
  mismatched current input, unstable reads, pending interactions or unavailable
  native observations cannot authorize terminal verification.
- The pinned V2 event order (OpenCode v2.2.5, commit `9bbb8ce`,
  `core/session/runner/llm.ts:174-181` and
  `core/session/execution.ts:122-124`) calls `experimental.idle` before
  publishing the corresponding `session.execution.succeeded`. The idle report is now tied to
  the current admitted user/synthetic input, the durable `execution.started`
  sequence and the latest relevant event sequence. A later success preserves
  that report only when its sequence follows the matching idle fence and native
  session context still has the same input. Delayed older events cannot replace
  a newer execution's report. New starts/inputs, failure/interruption, shell
  transitions, stream loss, missing sequences and mismatched lineage invalidate
  the observation.
- `experimental.idle` reports only the hook's listed shell/subagent/image work.
  A zero count is not a complete process, PTY, descendant, or resource
  quiescence inventory; unknown or lost reports remain unknown.
- Process-replacement recovery remains explicit: cancellation retains the same
  attempt, session, workspace, route, dirty files and accounting; explicit
  Resume adds one journaled input to that attempt, and duplicate command replay
  does not enqueue another input.

## Deterministic regression coverage

The focused fixtures exercise active-versus-idle timestamps, absent handles,
stale success and unfinished assistant messages, pending worker input and
worker-location approvals, active/detail-read and cancellation races, native
transport invalidation/recovery, exact input lineage, and same-attempt explicit
cancel/resume. The registered progress hook/event-listener regression executes
`execution.started → experimental.idle → execution.succeeded`, confirms the
matching terminal event, then verifies an older success arriving after a newer
idle report is ignored and a subsequent shell transition invalidates the
report.

These checks use controlled native API and hook/event fixtures. They do not
claim to establish complete background-resource quiescence or production
activation behavior. No product activation, service restart, or real worker
continuation was performed for this change.

and a durably admitted handoff reminder preventing honest completion. The repair
scopes execution cursors to their listener and invalidates only observations
owned by that listener on stream loss, end or disposal. Fresh execution/idle

current assignment or its durably admitted, exactly owned reminder, and requires

claims without that binding are not silently treated as current. The older
artifact-evidence fixture now supplies explicit current-input completion and
