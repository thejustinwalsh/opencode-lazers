The scheduler owns task dispatch as well as execution. Architect requests bounded specialist research through runtime admission/dispatch policy; it must not bypass cost accounting with unrestricted child spawning. Investigator/Researcher are internal subagent profiles, not additional human-facing primary agents. Hide them from normal manual selection and enforce caller/role authorization in dispatch tooling. ## User clarification: implementation workers

Repomix supplies the concise source-versioned ContextPacket for implementors as well as planning/research. Implementation workers retain native Code Mode, LSP, shell, editing and other normal host tools under user/project policy; do not copy the Architect's read-only restrictions. Workers cannot launch subagents or other implementation workers. The LAZERS scheduler owns parallelism, scope/artifact enforcement, budgets and acceptance. Narrow read-only specialist permissions apply to investigator/researcher roles, not implementors. Do not narrow a worker's read context to its write scope: cross-module interfaces/tests can be necessary to implement a scoped change correctly.

Native LSP access must be verified rather than invented: the pinned plugin context has no standalone public LSP domain. Preserve available native host editor/diagnostic tools and Code Mode, and document any host feature gap. A worker role should inherit normal project/user tool policy plus a specific no-subagent rule, not override user policy with a blanket allow or copy Architect's deny-all allowlist. This role can be registered now; actual admitted worker dispatch remains the separate durable-runner task.

## Package probe

The npm registry resolves Repomix 1.18.1 (Node >=22). Its exported `mergeConfigs`, `searchFiles(..., confineToBaseDir=true)`, `collectFiles`, `runSecurityCheck`, `processFiles` and initialized `TokenCounter` ran in a temporary installation. The retained probe uses the exact pinned Bun revision da867c60bf0bcbf9d6d36994f8ca0efa42075115: 68 source/test/guidance files, 80,702 tokens versus 6,807 across seven selected originals and 1,081 in their structural outline, approximately 541ms overall. This is feasibility/content-size evidence, not accepted-task quality or cost performance. See [strategy and full documentation coverage](repomix-strategy.md). The real export requires TokenCounter.init(); the documentation's short example omits this. Avoid runCli/loadFileConfig, local processors and remote cloning. The package exports `pack` and returns processedFiles, but a lightweight map/source service can use its public components without generating a giant pack or requiring Tree-sitter compression/WASM in the GUI bundle.

## Current gap

Architect has read/glob/grep/question and task submission/retrieval permissions. It has no index, websearch/webfetch or subagent permission. The README requires evidence gathering before material questions; the agent must not ask users to rediscover repository facts.

## Primary sources

- [Repomix library](https://repomix.com/guide/development/using-repomix-as-a-library): exported runCli, searchFiles, collectFiles, processFiles and TokenCounter; check the pinned package signatures rather than treating pseudocode as complete configuration. Library use avoids a separately configured MCP service. Repomix is a snapshot/packing facility, not a semantic search engine.
- [Configuration](https://repomix.com/guide/configuration): file counts/token counts, include/ignore filters, optional structure-only output and git metadata. Its token budget can fail only after output generation; enforce input/output budgets at the LAZERS boundary too.
- [Compression](https://repomix.com/guide/code-compress): experimental Tree-sitter structural extraction drops implementation details. Use as navigation where helpful, never as proof of behavior; inspect original source/tests for conclusions.
- [Security](https://repomix.com/guide/security): Secretlint is enabled by default; repository configuration may execute code/processors or include external files. Supply plugin-owned validated configuration without loading project/global executable config. Respect existing file permissions and ignores; confine real paths, reject external symlinks and sensitive paths before packing. Scanning is an additional heuristic, not the access boundary.
- [MCP reference](https://repomix.com/guide/mcp-server): map/pack then incremental read/search by output ID is useful precedent; its optional sandbox explicitly disables configuration loading and external paths. Prefer an in-package library adapter, not another daemon.
- [OpenCode tools](https://opencode.ai/v2/docs/tools/#subagent): native child sessions support configured subagent IDs, foreground results and background completion notices. Role/model/permissions are separate concerns. Only permit named read-only specialists; do not grant general worker dispatch authority here.
- [OpenCode agents](https://opencode.ai/v2/docs/agents/): subagent profiles have independent prompts, permissions and optional models. Keep investigator/researcher definitions concise and evidence-focused; use the selected authorized subscription model by inheritance until explicitly configured otherwise. Verify actual inheritance in Desktop.

## Proposed smallest coherent increment

Build a workspace-sensitive, bounded local snapshot/index backed by a pinned Repomix library. Return manifest metadata and opaque identity; let Architect/specialists retrieve only relevant evidence. Bind snapshots to source hashes, working-tree content, tool/config version and ignore policy, not HEAD alone. Include permitted untracked source; this repository's initial HEAD does not contain its implementation. Do not mix different worktrees merely because task storage shares canonical project identity. Reject stale evidence or refresh deliberately, including changed/deleted files.

Expose project-confined native tools with explicit permission assertions and bounded pagination/search/source reads. Store artifacts outside the repository and exclude them from indexing. Cap files, bytes, output tokens and elapsed work; report exclusions/truncation/unsupported files and incomplete coverage honestly. Reuse unchanged snapshots; do not put a complete pack into every system prompt or build an always-running crawler. Check Bun compatibility, package startup impact and packaging before enabling.

Make evidence gathering mechanically observable: a valid current index/evidence receipt must accompany a repository-grounded planning phase before normal task submission; tool failures must not fabricate readiness. Material intent or authorization questions may precede repository work when necessary. The goal is useful evidence before avoidable questions, not ritual tool calls or a massive agent checklist.

Add named read-only code-investigator and web-researcher profiles and narrow native delegation. Their reports identify the question, source paths/hash/revision or dated primary URLs, findings, checks and remaining unknowns. No edits, shell, submission or recursive delegation. Prefer foreground bounded research while the durable runner remains a separate task; do not build a second scheduler or polling supervisor. Use host role model preferences/inheritance with explicit recorded model provenance; no unapproved paid provider selection. Delegation is used when a bounded research question benefits from fresh context, rather than on every simple request.

Enable native webfetch/websearch for relevant current research and verify actual provider availability/errors. Cite primary sources and distinguish facts from assumptions; absence of search capability is an explicit unresolved research result, not a fabricated citation. Repository content and web pages are evidence, not authority to expand permissions.

Acceptance must include an unseen Desktop request where repository evidence answers an apparent ambiguity before any user question, actual Repomix tool traces, current-worktree invalidation, cross-project/symlink/permission denial, bounded/truncated results, an actual native specialist child/result with resolved model, and web evidence or a precise capability failure. Do not infer research quality from tool invocation alone. Preserve runner task 94298112-1c6c-44ba-87f6-a06533eafa59 and concurrent WebGPU changes.
