# Spike 024: Final prose speech

Question: Can optional local auto-speech consume authoritative final-text events without guessing from raw deltas or leaking commentary/code, while preserving manual replay during later work?

Increment: Keep the last successful completed final manually replayable and add opt-in, deduplicated speech for identified final parts. Unmarked providers speak only after a successful execution.

Scope: `src/webgpu/speech.ts`, `speech-events.ts`, `speech-playback.ts`, `read-aloud.tsx`, their focused tests, the production event-path test, and this spike record. No inference-engine, transport, or feature-setting changes.

Implementation: Manual replay now searches for the last successful completed final independently of the current turn. The existing speaker stays in its composer-pill position and remains directly clickable for replay/Stop. A separate native composer-pill menu and the `LAZERS → Toggle automatic read aloud` command (default `ctrl+shift+alt+s`, user-rebindable) control auto mode; it defaults off. Enabling it primes Web Audio from the user gesture. A scoped `session.text.ended` listener speaks only explicit `final_answer` parts as delivered; unmarked text is buffered by assistant message and used only after a stopped final step and successful execution. Per-session/message/ordinal deduplication is retained for the lifetime of the opt-in listener and survives event-stream reconnects. Markdown fences and comments are filtered incrementally across text parts. Stop aborts current and prefetched work and suppresses later parts from that turn; navigation, feature disablement, and plugin disposal cancel stale work.

Native boundary: In pinned OpenCode 2.2.5, `ComposerPill` is the supported composer-adjacent action and `Command` supports native shortcuts. The public GUI `SlotMap` has `window.bottom`, `session.header`, `session.location.menu`, and `session.panel.end`, but no fixed-right composer action slot (`node_modules/@opencode/plugin/dist/gui/registries.d.ts:599-698`). No fake slot, DOM reparenting, titlebar/header substitution, or modifier-click behavior is used. Phase-bearing replayable `session.text.ended` events carry `assistantMessageID`, `ordinal`, `text`, and native metadata (`node_modules/@opencode/schema/dist/session-event.js:332-364`); raw deltas are not subscribed to. Inference runtime and all six existing feature settings are unchanged.

Verification: The focused tests drive the production event coordinator and registered native controls with a `runtime.speak` spy. They cover replay during active work, Stop, raw-delta/reasoning/commentary canaries, identified final parts, unmarked successful completion, split code fences/comments, duplicate delivery after reconnect, and stale sessions. Focused tests pass (20 tests / 78 assertions); the full Bun suite passes (225 / 2,186 assertions); `bun run verify` and `bun run build:gui` pass. The GUI build retains the existing upstream ONNX Runtime `import.meta` CommonJS warnings. One initial full-suite run hit a one-millisecond catalog timestamp mismatch in `src/runner/tools.test.ts`; the immediate full-suite rerun passed.

Desktop driver review: Pending. No Desktop browser is connected in this execution, so this is not claimed as assembled-Desktop evidence. Driver checklist: in the built Desktop bundle, verify (1) the prior completed answer remains available while a new turn is active, (2) auto mode toggles from the composer-pill menu and native shortcut, (3) only final prose is spoken once while text parts arrive, and (4) Stop halts active playback and prevents queued/later parts. The fixed-right composer slot remains an upstream API gap; keep the existing placement until the pinned host exposes one.
