## Release gates and trust limits

1. **Host dependencies:** both `bun audit --json` and `bun audit --production --json` report moderate advisories for `glob` and `minimatch`. `bun why` traces them to pinned `@opencode/plugin` → host utility/AI dependencies, including glob 13.0.5/10.5.0 and minimatch 10.2.5/9.0.9. Patched versions are glob 14.0.2 and minimatch 11.0.1. These cross major-version boundaries and the host owns its runtime dependencies; local overrides would not repair an installed Desktop host. Upgrade the host/dependency pin and repeat compatibility verification before broad release. [Glob advisory](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4), [minimatch advisory](https://github.com/advisories/GHSA-g3hv-75wg-m249).
2. **Driver and lifecycle coverage:** real tests cover one Apple GPU and OpenCode 2.2.5. An all-day residency/speech soak, repeated sleep/wake, low-memory conditions, actual multi-window crash/takeover, network interruption during first download, and Windows/Linux driver coverage remain release criteria. Fault injection covers ownership races but is not real multi-window/hardware evidence.
3. **Native execution:** a client deadline does not preempt an ONNX forward pass or a wedged driver. Continue waiting for actual cleanup before another allocation. Process/driver hangs require host recovery; do not introduce `Promise.race` disposal that permits overlapping GPU use. [ONNX WebGPU resource guidance](https://onnxruntime.ai/docs/tutorials/web/ep-webgpu.html).
4. **Trust boundary:** installed plugins and the authenticated local service are trusted. Private mailbox naming is not authorization against hostile authenticated code; don't expose it to untrusted clients. A same-user/privileged filesystem attacker or hostile Electron renderer is outside this cache-integrity guarantee. Host Electron isolation, IPC sender validation and framework updates remain necessary. [Electron security guidance](https://www.electronjs.org/docs/latest/tutorial/security/).
5. **Quality, data and distribution:** run the separately bounded [task-review evaluation](parallel-task-review-evaluation.md) before claiming a quality gain. Review evidence/history persists in plugin-scoped storage; weights persist until cleanup, while microphone PCM and speech buffers are memory-only in this plugin. The host may retain ordinary tool/chat transcripts. Preserve upstream attribution and checkpoint licensing for distribution. Experimental GUI APIs and the private package flag remain explicit release limitations.
