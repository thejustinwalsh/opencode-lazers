## 0. Findings that shape the plan

1. **The project already has a size threshold.** `FILE_SIZE_WARNING_LINES = 1_000` in `src/runner/scope.ts:197`. The runtime's scope review warns when a non-test source file goes past 1,000 lines (`crossed`), or grows by 40 or more lines while already over it (`grew`). The size targets below use that number, so nothing is arbitrary.
2. **Almost every test drives the public surface.** All 332 tests in `runtime.test.ts` call `tick()`, `command()` or `startTask()` on a real Git fixture, and the file has no `describe` blocks. Tests therefore do not have to move for code to move. Splitting the test file is a separate track, grouped by topic.
3. **Tests reach a few private members by casting, monkeypatching or `Reflect.get`.** A move must not break these silently: a patch that no longer intercepts can still pass, or hang.

## 2. Target shape

### Technique: move without rewriting

Each new module is a class constructed with a dependency object, the way `TakeoverDeps` and `AdoptionExecution` already work. To keep the bodies of moved methods byte-identical, each module declares private members under the same names the bodies already use:

- `private get store()`, `host`, `owner`, `directory`, `now`
- `private readonly hold: RuntimeJournal["hold"]`, and so on for other callbacks

So `this.store.plan(...)` and `this.hold(...)` compile unchanged inside the module. Tidying those aliases is a later, separate change.

**Shared types (new in step S2).**

- `runtime-core.ts` exports `RuntimeCore = { store, host /* the takeover-aware one */, projectID, owner, directory, dataDirectory, now, progress }` and `RetickRequest = () => void`.
- Every module's constructor is `(core: RuntimeCore, deps: XDeps)`.
- Modules depend on each other with `import type` only. They never import `runtime.ts` at runtime; existing modules already use `import type { TaskRuntime }`, which is erased.

**Forwarders keep the rest of `runtime.ts` unchanged during the move.** When region X moves, the coordinator keeps a one-line private forwarder for each X member still called by code in `runtime.ts`, for example `private hold(...a: Parameters<RuntimeJournal["hold"]>) { return this.journal.hold(...a) }`. Two rules make test patches keep working:

- Callbacks in the dependency objects are lazy arrows through the coordinator, `(...a) => this.verify(...a)`, so a test that patches the runtime instance still intercepts.
- The members in finding 3 keep their coordinator forwarders until step S21 migrates those tests.

With forwarders in place, any region can move once S2 has landed. That lets the order follow the feature work below rather than only the coupling.
