## Description

On top of the port (which, rebased onto v0.3.0's core, needs the changes below):

1. `feat(zoo): add createD1Decider on the ported D1 model and its Q8 loader`: the public runner
   (`createD1Decider`, `systemOne(state, questions)` scoring yes/no, choice and rubric questions with
   the checkpoint's calibration temperatures), a tokenizer on tokenizers.js, state-dict hooks that
   reorder and stack native-Q8 rows without dequantizing, `models.d1.D1_OMNI_600M` (original float
   checkpoint, and a caller-supplied Q8 one; no derivative weights are hosted). The model and runner
   own their execution and upload lifetimes, so a failed call or a dispose frees every buffer. Row
   remaps and stacks refuse a weight with per-group offsets rather than drop them.
2. `test(zoo): cover D1 prompts, tokenizer, quantized hooks and image preprocessing`: Node tests.
3. `test(zoo): qualify D1 against pinned PyTorch vectors on the GPU`: opt-in GPU suites and the
   vectors file.
4. `docs(zoo): add the D1 decision model page`: how to load a locally converted Q8 checkpoint and
   how to produce one with `tools/python`.

## Testing instructions

```sh
pnpm install --frozen-lockfile
pnpm typecheck && pnpm lint && pnpm format:check
pnpm --filter runntime test:unit          # 77 files, 1353 tests
pnpm build                                                    # includes the docs page
cd packages/runntime
W=/test/.weights
VITE_D1_Q8_QUALIFICATION_MODE=q8 VITE_D1_Q8_MODEL_URL=$W/d1-omni-600m-text-q8.safetensors \
  VITE_D1_Q8_TOKENIZER_URL=$W/d1-tokenizer.json VITE_D1_Q8_ARTIFACT_SHA256=<sha of the artifact> \
  pnpm exec vitest run --project gpu test/zoo/d1
```

- Node: `prompt.test.ts`, `tokenizer.test.ts`, `public.test.ts`, `stateDictHooks.test.ts` (Q8 row
  remap and stacking keep scales; mixed float and quantized members refused; offsets refused) and the
  new `image.test.ts`: the tile and thumbnail plan worked out from LFM2-VL's smart-resize rules
  (512 x 512 kept, 32 x 32 raised to 256 x 256, 1024 x 1024 tiled 2 x 2 with a 512 thumbnail, 100 x
  50 to 192 x 384), the antialiased bilinear resize on hand-computed triangle-filter taps, and patch
  normalization (byte 0 to -1, 255 to 1).
- GPU: `q8.gpu.test.ts` (the Q8 loader against `reference-vectors.json`, probability tolerance 0.04)
  and `qualification.gpu.test.ts` (modes `baseline`, `repaired`, `correction`: tokenizer ids and
  answer probabilities within 0.001 of the transformers reference, plus cleanup, serialization,
  abort, disposal and device recovery).

## Known limits

- **The playground files are the collaborator's, verbatim.** `playground/d1/{snake,webcam,triage,mod,
bench,...}`, `public/cats.jpg` and `vite.config.mjs` (which fixes port 5199 with `strictPort`) arrive
  inside the collaborator's commits `1a9a1a8` and `9a0b58c`. If the maintainers do not want demos in
  this series, drop those two commits; nothing in the later commits depends on them.
- **Fixtures.** `playground/d1/reference-vectors.json` (228 lines) holds tokenizer ids and
  per-case answer probabilities produced by transformers 5.22.2 with torch 2.15.0, float32 on CPU, on
  `LiquidAI/d1-omni-600M` revision `02b55d7076f15129e59ab3f94783f32c4b088674`; the generator
  (`reference.py`) is in the fork's records (`d1-reference`), not in this tree. The weights are under
  the LFM Open License v1.0; no licence statement for the derived numbers exists in the history, so
  redistribution is **not established**. `playground/d1/public/cats.jpg` (173 KB) was added by the
  collaborator's commit with no stated source or licence: **unsourced**, and no test in the series
  uses it (only the demos do).
- Q8 parity was measured on one machine; tolerance 0.04 is the fork's, looser than the float
  qualification's 0.001.
- Commits 1 to 3 do not typecheck on their own against v0.3.0 (the port uses `derivedTensor`, removed
  upstream); the branch tip is green. They are kept as cherry-picked to preserve authorship.
