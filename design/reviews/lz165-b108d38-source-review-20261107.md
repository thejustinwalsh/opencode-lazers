## P1: async generation registration is dropped by the main IPC adapter

Candidate `ModelLease.registerGeneration` now returns `void | Promise<void>`.
When host-loss cleanup is pending it returns a promise that waits for cleanup
and then registers the new generation. But unchanged `src/webgpu/main.ts` calls
this method without returning its result from the registered IPC handler.

Consequently a renderer awaiting files.registerGeneration can receive success
before its generation is registered, then race into acquisition with the old
registration. A delayed rejection is detached from the IPC caller rather than
reported as registration failure. The generation wait also is not tracked with
the main provider's in-flight lease operations before shutdown.

Return/track the actual registration result through the existing IPC handler,
using the existing operation tracker. Add a registered-main regression that
holds the host-loss cache drain: the registration call must remain pending,
then succeed only after registration or reject to the caller if drain fails.
Keep the existing same-provider, exact owner/token, new-page/reset-generation,
stale reply, foreign-window and process-restart protections. This is a thin
adapter correction; no new service, control API or proof protocol is needed.

The new low-level lease tests and positive registered reload fixture are useful,
but do not establish the pending-registration IPC contract. Root did not run a
production reload against this candidate or mutate its original checkout.
Use the same original165worker for correction; Root's earlier file reservations
are released. Do not record the pending human live gate as passed from tests.
