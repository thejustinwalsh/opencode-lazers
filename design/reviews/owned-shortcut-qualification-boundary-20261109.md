# Owned qualification: shortcut and source boundary

The retained verifier found no usable rendered variant action. The documented
Ctrl+T shortcut cannot pass through the current owned native bridge: CLI and RPC
accept only six bare keys, and Main sends key-down/up without modifier fields.
Searching model names for `max` again or setting a model through another API is
not a correction to this control gap.

**LZ-197** repairs that one behavior through the existing CLI/RPC/Main path, with
backward-compatible bare keys, correct modifiers and refusal rather than silent
plain-key input from an incompatible adapter. Tests cover the production path,
ownership/focus/generation/snapshot fences and lost/partial delivery. It has no
permission to operate the retained qualification instance during implementation.
Its disjoint verification scope does not replace LZ-181, LZ-182, LZ-195, the old
LZ-50 trial or the queued LZ-191 tooling audit.

The same owned instance/account/fixtures/verifier remain retained. No inference,
reload, restart, manifest edit or cleanup was performed as a result of this
research. Current Luna Default is not Luna Max. A newer bundle on disk and the
historical launch manifest are not proof of active code.

After reviewed integration and composition/build in the retained qualification
checkout, the supported activation proposal is:

1. Revalidate the exact retained service, native interaction state and a genuine
   quiet boundary across its loaded locations, including forms/permissions.
2. Use public `client.location.reload()` only on that owned service. It reloads
   all its loaded locations and can cancel pending forms/permissions; it is not
   a scoped worktree call or permission to reload the driving service.
3. Use the actual native **Settings → Extensions → Plugins → LAZERS → Reload**
   control, not an enable/disable toggle or Desktop restart. The verifier has
   source evidence for this control but has not yet observed/clicked its live row.
4. Reobserve current adapter/window/generation and effective keyboard capability,
   then use supported native input to select and read back exact Luna Max.
   Preserve every refusal and never replay ambiguous input.
5. Establish relevant active server/GUI behavior before claiming the current
   candidate: distinguish new bridge capability, trajectory input labels and
   source-context task retrieval from filesystem or manifest observations. Retain
   any unproven layer explicitly and do not claim the full walkthrough passed.

Native variant selection and loaded-source qualification remain pending. The
repair's tests/build are not substitutes for those observations. Local semantic
self-review was unavailable after GPU device loss; no pass or change to inference
