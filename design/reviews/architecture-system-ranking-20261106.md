Companion to [the full review](architecture-review-20261106.md), [read-only data](architecture-inventory-20261106.json) and [offline C4 views](architecture-c4-20261106.html). Rank orders architectural fitness: clear authority, appropriate native reuse, recoverability, evidence and maintenance cost. **5 = strong boundary; 4 = sound with gaps; 3 = mixed; 2 = consequential competing behavior; 1 = unusable.** Scores are engineering judgments, not benchmark measurements. P1/P2 labels prioritize concrete user impact separately from score. No P0 was established.

The highest-value unification is one authority per lifecycle decision, not one table or one framework for every purpose. Preserve native/session history, specification history, artifact/check evidence, current projections and UI preferences where they answer different questions. A competing rule is harmful when the same command or fact has two authoritative interpretations, as in A1/A3/A4. A slow activity is harmful when it blocks unrelated control progress, as in A2. None of these requires an architecture replacement.
